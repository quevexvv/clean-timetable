# Проверки версии 0.1.0

Дата: 2 ноября 2026. Данные расписания могут обновляться независимо от расширения.

## Автоматические проверки

`npm test`: 32 поведенческие проверки через `node:test` и jsdom. Проверяются область постоянного правила, разовые пропуски, восстановление поверх правила, независимость групп и преподавателей, даты, последовательная запись, ошибки чтения/записи, проверка отправителя сообщений, расшифровка после загрузки, повторное построение таблицы, скрытие одного преподавателя под общим заголовком, адаптер Chromium, сборка манифеста и ответ service worker в имитации `chrome` API.

HTML-примеры реальных недель: `tests/fixtures/tpu-week10.html` и `tpu-week11.html`. Исходные страницы скачаны с сайта; читаемые названия сверены с DOM после штатной расшифровки в браузере. Удалены скрипты, внешние ресурсы и технические метаданные, сохранена структура таблицы.

- Неделя 10, 2–7 ноября: распознаются 30 занятий.
- Неделя 11, 9–14 ноября: распознаётся 31 занятие. В том числе два преподавателя лабораторной по физике под общим заголовком; скрытие одного не затрагивает другого.
- Постоянное правило для практики английского у Макаровских совпадает с двумя занятиями на неделе 10 и тремя на неделе 11. Разовый пропуск с недели 10 на неделе 11 не действует.

`npm run check` проверяет синтаксис JS. `npm run lint` использует `web-ext` с ошибкой при любом предупреждении. `npm run build` собирает только содержимое `extension/`, без тестов, инструментов и документов. `npm run build:chromium` копирует те же исходники в `dist/chromium/`, заменяет манифест и добавляет адаптер API.

Итог: 32/32 теста прошли, синтаксис корректен, lint — 0 ошибок / 0 предупреждений / 0 замечаний, ZIP для Firefox и Chromium собраны. Повторная установка зависимостей из lockfile проверена командой `npm ci --ignore-scripts --offline --no-audit --no-fund` с локальным кешем; удалённый CI не запускался.

## Сборка Chromium

`npm run build:chromium` создаёт `dist/chromium/` и `dist/tpu-schedule-filter-chromium-0.1.0.zip`; проверено 10 ноября 2026. В сгенерированном манифесте: service worker `chromium-background.js`, `minimum_chrome_version` 109, `chromium-compat.js` первым в content script, без `browser_specific_settings`. Тесты подтверждают, что файлы `extension/` после сборки не изменяются, а адаптер превращает Promise-ответ фонового обработчика в `sendResponse`.

Запуск в настоящем Chromium, Chrome, Edge, Brave, Opera, Vivaldi или Яндекс Браузере не выполнялся: в текущем окружении нет такого браузера. Проверены только сборка, манифест и адаптер API в Node.js. Загрузка `dist/chromium`, работа на живом сайте и сохранение после перезапуска требуют ручной проверки.

## Проверка интерфейса

В управляемом браузере на локальном стенде с разметкой ТПУ и CSS сайта проверены:

- меню «Настроить» и подтверждение точного постоянного правила;
- скрытие двух лабораторных ОС у Цапко без скрытия соседних предметов;
- отсутствие разделителя и вертикальное центрирование оставшегося занятия;
- показ скрытых занятий в полном виде и возврат одной лабораторной;
- сохранение результата после перезагрузки страницы;
- применение того же правила на соседней неделе: после возврата одной пары недели 10 остаётся скрыта одна пара, на неделе 11 скрыты две.

Этот стенд использовал адаптер localStorage вместо WebExtensions API. Он проверяет DOM и интерфейс, но не доказывает работу установленного расширения на живом сайте. `preview.jpg` — снимок строки 12:40 после скрытия ОС у Цапко: Ковин остаётся по центру своей ячейки.

## Загрузка в целевые браузеры

Через `web-ext run` в отдельных временных профилях успешно загружено неподписанное дополнение:

- Firefox **159.0**, официальный Linux-пакет Mozilla;
- Zen **1.24b**, Gecko **159**, исполняемый файл установленного Flatpak.

Оба запуска сообщили `Installed … as a temporary add-on`. Основные профили пользователя не изменялись. Это подтверждает загрузку дополнения; ручные действия в установленном расширении на живом сайте через эти браузеры не проверены. Объявленный минимум Firefox 142 не проверен отдельным запуском.

### Проверка пользователем в Zen Flatpak

При первоначальной загрузке пользователь сообщил об отсутствии панели. Проверка из песочницы Zen 1.24b показала недоступность файлов проекта в `~/Projects`; ZIP в папке «Загрузки» доступен. После загрузки архива пользователь подтвердил: «все, я загрузил архив и норм». Это подтверждает устранение проблемы загрузки; отдельные сценарии фильтрации и сохранение после полного перезапуска этим сообщением не проверены.

При сохранении после обновления дополнения держать прежний ID.

## Правки UX/UI после проверки пользователем

- У полностью скрытых ячеек нейтрализуется inline-заливка сайта с `!important`. В полном расписании и после возврата восстанавливаются исходное значение и его приоритет; посторонние стили сохраняются.
- Счётчик показывает только скрытые занятия: «Скрыта 1 пара», «Скрыто 2 пары», «Скрыто 11 пар». Проверены формы 0/1/2/5/11/21/22.
- «Настроить» использует стандартный маркер раскрытия и область высотой 26 px; в полном виде кнопка «Вернуть эту пару» доступна без раскрытия меню.
- Успешное действие закрывает меню; фокус переходит к видимому управлению соседней или возвращённой пары, кнопке возврата либо переключателю полного вида. В локальном браузерном стенде проверены Enter и последовательность Tab → Tab → Enter для пропуска в полном виде.
- Независимый субагент осмотрел пользовательский и итоговый снимки, проверил diff и не нашёл блокирующих проблем. Это не подтверждает полную доступность и не заменяет проверку клавиатуры в установленном Zen.
